SD-WAN path selection & failover

Give a FortiGate branch two internet links, measure them with SLA probes, steer traffic per application, then degrade a link with latency and loss to watch the decision change.

Objective

Give a FortiGate branch two internet links, measure them with SLA probes, steer traffic per application, then degrade a link with latency and loss to watch the decision change.

Prerequisites

  • EVE-NG (Community or Pro) with the images listed in the topology.
  • Console access to every node; basic CLI knowledge.

Topology & addressing

DeviceInterfaceAddress / role
FG-BRANCHwan1 / wan2100.64.1.2/30 · 100.64.2.2/30
ISP-1 / ISP-2eth1 → branch100.64.1.1 · 100.64.2.1
FG-HQLAN probe server10.1.0.10

Build it step by step

1. Members and zone

Both WAN interfaces in one SD-WAN zone, each with its gateway.

FG-BRANCH
config system sdwan
    set status enable
    config members
        edit 1
            set interface "wan1"
            set gateway 100.64.1.1
        next
        edit 2
            set interface "wan2"
            set gateway 100.64.2.1
        next
    end
end

2. SLA probe

500 ms probes; a member is dead after 3 failures and back after 5 successes.

FG-BRANCH
config system sdwan
    config health-check
        edit "SLA-HQ"
            set server "10.1.0.10"
            set protocol ping
            set interval 500
            set failtime 3
            set recoverytime 5
            set members 1 2
            config sla
                edit 1
                    set latency-threshold 100
                    set jitter-threshold 20
                    set packetloss-threshold 2
                next
            end
        next
    end
end

3. Steering rules

VoIP stays on wan1 while it meets the SLA; bulk traffic prefers wan2.

FG-BRANCH
config system sdwan
    config service
        edit 1
            set name "VOIP"
            set mode sla
            set dst "VOIP-SERVERS"
            config sla
                edit "SLA-HQ"
                    set id 1
                next
            end
            set priority-members 1 2
        next
        edit 2
            set name "BULK"
            set mode manual
            set dst "BACKUP-SERVERS"
            set priority-members 2 1
        next
    end
end

4. Degrade a link

On the ISP-1 Linux node, add delay and loss, then remove it.

ISP-1 (Linux)
# add 150 ms delay and 5 % loss towards the branch
tc qdisc add dev eth1 root netem delay 150ms loss 5%
# restore
tc qdisc del dev eth1 root

Verify

CommandWhat you should see
diagnose sys sdwan health-checkPer-member latency, jitter, loss and SLA state.
diagnose sys sdwan serviceWhich member the VOIP rule selects now.
diagnose sniffer packet any 'icmp' 4Probes leaving on both members.
execute ping-options source … + pingContinuous test traffic while you degrade the link.

Break it, then fix it

Introduce each fault, observe the symptom, then open the hint.

breakProbe server unreachable on one member

That member is always dead. Check routing and firewall policy for the probe path.

breakThresholds too tight

Traffic flaps between links. Raise thresholds or recovery time.

breakRule never matches

Traffic falls to the implicit rule. Check rule order and the destination object.

Key takeaways

  • Detection time ≈ interval × failtime. Tune it per application.
  • A link can be up and still unusable: SLA probes catch that.
  • Always test failover with real degradation, not only a cable pull.
