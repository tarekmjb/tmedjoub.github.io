FortiGate HA cluster

Build an active-passive FGCP cluster with two heartbeat links, monitored interfaces and session pickup, then fail the primary and check that sessions survive.

Objective

Build an active-passive FGCP cluster with two heartbeat links, monitored interfaces and session pickup, then fail the primary and check that sessions survive.

Prerequisites

  • EVE-NG (Community or Pro) with the images listed in the topology.
  • Console access to every node; basic CLI knowledge.

Topology & addressing

DeviceInterfaceAddress / role
Clusterport1 (WAN)203.0.113.2/29
Clusterport2 (LAN)10.1.0.1/24
FG-A / FG-Bport5 (mgmt)10.99.0.11 · 10.99.0.12
Heartbeatport3 / port4169.254.0.x (FGCP, automatic)

Build it step by step

1. Same firmware, same model

FGCP only forms between identical models and versions. Check with get system status.

FG-A / FG-B
get system status

2. HA settings (primary)

Two heartbeat links, monitored data ports, session pickup.

FG-A
config system ha
    set group-name "FG-CLUSTER"
    set group-id 10
    set mode a-p
    set password ENC ********
    set hbdev "port3" 50 "port4" 50
    set session-pickup enable
    set override disable
    set priority 200
    set monitor "port1" "port2"
    set ha-mgmt-status enable
    config ha-mgmt-interfaces
        edit 1
            set interface "port5"
            set gateway 10.99.0.254
        next
    end
end

3. Secondary

Same settings, lower priority. The config syncs from the primary once the cluster forms.

FG-B
config system ha
    set group-name "FG-CLUSTER"
    set group-id 10
    set mode a-p
    set password ENC ********
    set hbdev "port3" 50 "port4" 50
    set session-pickup enable
    set override disable
    set priority 100
    set monitor "port1" "port2"
end

Verify

CommandWhat you should see
get system ha statusBoth units listed, primary and secondary identified.
diagnose sys ha checksum clusterIdentical checksums on both units.
execute ha manage 1 adminCLI on the secondary from the primary.
diagnose sys session list (on secondary)Sessions present when session-pickup is on.

Break it, then fix it

Introduce each fault, observe the symptom, then open the hint.

breakDifferent firmware

No cluster forms. Upgrade one unit before joining.

breakSingle heartbeat link cut

Both units become primary (split brain). Always use two heartbeat links.

breakMonitored port down on the primary

Failover to the secondary, as expected. With override disabled, it stays there after recovery.

Key takeaways

  • Two heartbeats, monitored ports and session pickup are the minimum.
  • Override disabled avoids a second failover when the old primary comes back.
  • Test failover with live sessions, not just pings.
