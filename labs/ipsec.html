IPsec site-to-site VPN

Connect two sites over the internet with a route-based IKEv2 tunnel (VTI): AES-256, SHA-256, DH group 14 with PFS, then troubleshoot the classic negotiation failures.

Objective

Connect two sites over the internet with a route-based IKEv2 tunnel (VTI): AES-256, SHA-256, DH group 14 with PFS, then troubleshoot the classic negotiation failures.

Prerequisites

  • EVE-NG (Community or Pro) with the images listed in the topology.
  • Console access to every node; basic CLI knowledge.

Topology & addressing

Build it step by step

1. IKEv2 proposal, policy and keyring

Phase 1 parameters must match on both peers.

R1
crypto ikev2 proposal PROP-AES256
 encryption aes-cbc-256
 integrity sha256
 group 14
crypto ikev2 policy POL-1
 proposal PROP-AES256
crypto ikev2 keyring KR-R2
 peer R2
  address 198.51.100.2
  pre-shared-key <redacted>
crypto ikev2 profile PROF-R2
 match identity remote address 198.51.100.2 255.255.255.255
 authentication remote pre-share
 authentication local pre-share
 keyring local KR-R2

2. IPsec profile (phase 2)

ESP AES-256 / SHA-256 with PFS group 14.

R1
crypto ipsec transform-set TS-AES256 esp-aes 256 esp-sha256-hmac
 mode tunnel
crypto ipsec profile IPSEC-R2
 set transform-set TS-AES256
 set ikev2-profile PROF-R2
 set pfs group14

3. Tunnel interface and routing

The VTI is a normal interface: route the remote LAN into it. MSS is clamped for the IPsec overhead.

R1
interface Tunnel0
 ip address 10.255.0.1 255.255.255.252
 ip mtu 1400
 ip tcp adjust-mss 1360
 tunnel source GigabitEthernet0/0
 tunnel destination 198.51.100.2
 tunnel mode ipsec ipv4
 tunnel protection ipsec profile IPSEC-R2
!
ip route 192.168.2.0 255.255.255.0 Tunnel0

Verify

CommandWhat you should see
show crypto ikev2 saStatus READY.
show crypto ipsec saencaps and decaps counters both increase.
show interface Tunnel0up/up, tunnel protocol IPSEC/IP.
ping 192.168.2.1 source 192.168.1.1Success; the first packet may be lost while the SA builds.

Break it, then fix it

Introduce each fault, observe the symptom, then open the hint.

breakPre-shared key mismatch

IKE_AUTH fails; debug shows an authentication failure. Re-enter the key on both sides.

breakDifferent proposals

NO_PROPOSAL_CHOSEN in the logs. Compare encryption, integrity and DH group.

breakTunnel up, no traffic

Encaps stays at 0: the route to the remote LAN is missing, or a firewall blocks UDP 500/4500.

Key takeaways

  • Route-based VPNs scale: add a route (or BGP) instead of editing crypto ACLs.
  • Read the error: NO_PROPOSAL_CHOSEN, AUTH_FAILED and TS_UNACCEPTABLE each point to a different fix.
  • Clamp MSS on tunnels to avoid fragmentation problems.
