Objective

Build eBGP between three autonomous systems, advertise LAN prefixes, then change the path R1 uses to reach AS65003 with local preference, without touching the shortest AS path.

Prerequisites

  • EVE-NG (Community or Pro) with the images listed in the topology.
  • Console access to every node; basic CLI knowledge.

Topology & addressing

Build it step by step

1. Bring up eBGP sessions

One neighbor per directly connected link. Activate them under the IPv4 address family.

R1
router bgp 65001
 bgp router-id 1.1.1.1
 bgp log-neighbor-changes
 neighbor 10.0.12.2 remote-as 65002
 neighbor 10.0.13.2 remote-as 65003
 address-family ipv4
  neighbor 10.0.12.2 activate
  neighbor 10.0.13.2 activate
  network 172.16.1.0 mask 255.255.255.0

2. Advertise the LANs

A network statement only works if the exact prefix is already in the routing table.

R3
router bgp 65003
 bgp router-id 3.3.3.3
 neighbor 10.0.23.1 remote-as 65002
 neighbor 10.0.13.1 remote-as 65001
 address-family ipv4
  neighbor 10.0.23.1 activate
  neighbor 10.0.13.1 activate
  network 172.16.3.0 mask 255.255.255.0

3. Change the best path

By default R1 reaches 172.16.3.0/24 directly (shortest AS path). Raise local preference on routes from R2 so R1 prefers the path through AS65002.

R1
route-map FROM-R2 permit 10
 set local-preference 200
!
router bgp 65001
 address-family ipv4
  neighbor 10.0.12.2 route-map FROM-R2 in
!
clear ip bgp 10.0.12.2 soft in

Verify

CommandWhat you should see
show ip bgp summaryBoth neighbors show a prefix count, not Idle/Active.
show ip bgp 172.16.3.0Two paths; best path via 10.0.12.2 with localpref 200.
show ip route bgp172.16.3.0/24 next hop 10.0.12.2 after the change.
traceroute 172.16.3.1 source 172.16.1.1Goes through R2.

Break it, then fix it

Introduce each fault, observe the symptom, then open the hint.

breakWrong remote-as on one side

Session flaps between Idle and Active; logs show a NOTIFICATION with "bad peer AS". Fix the ASN.

breakNetwork statement with the wrong mask

The prefix never appears in show ip bgp, because no exact match exists in the RIB.

breakRoute-map applied but nothing changes

Policy only applies to new updates. Run a soft inbound clear.

Key takeaways

  • eBGP is policy routing: you decide which path wins, not the metric.
  • Local preference is checked before AS-path length and stays inside your AS.
  • Always soft-clear after changing inbound policy.
