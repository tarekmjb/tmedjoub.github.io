OSPF multi-area

Build a backbone and two areas, summarise area 1 on its ABR, turn area 2 into a totally stubby area and secure adjacencies with MD5 authentication.

Objective

Build a backbone and two areas, summarise area 1 on its ABR, turn area 2 into a totally stubby area and secure adjacencies with MD5 authentication.

Prerequisites

  • EVE-NG (Community or Pro) with the images listed in the topology.
  • Console access to every node; basic CLI knowledge.

Topology & addressing

DeviceInterfaceAddress / role
R1Lo1–Lo410.1.0.1/24 … 10.1.3.1/24

Build it step by step

1. Areas and router IDs

Put each interface in its area. Loopbacks as point-to-point so the /24 is advertised as-is.

R2
router ospf 1
 router-id 2.2.2.2
 network 10.0.12.0 0.0.0.3 area 1
 network 10.0.23.0 0.0.0.3 area 0

2. Summarise area 1 on the ABR

Four /24s leave area 1 as a single 10.1.0.0/16 type-3 LSA.

R2
router ospf 1
 area 1 range 10.1.0.0 255.255.0.0

3. Totally stubby area 2

Both routers in area 2 must agree on the stub flag. no-summary on the ABR only.

R3 / R4
! R3 (ABR)
router ospf 1
 area 2 stub no-summary
! R4
router ospf 1
 area 2 stub

4. MD5 authentication on the backbone

Same key ID and key on both ends.

R2 / R3
interface GigabitEthernet0/1
 ip ospf message-digest-key 1 md5 <redacted>
!
router ospf 1
 area 0 authentication message-digest

Verify

CommandWhat you should see
show ip ospf neighborFULL adjacencies on every link.
show ip route ospf (on R3)One O IA 10.1.0.0/16 instead of four /24s.
show ip route (on R4)Only a default route O*IA from the ABR.
show ip ospf databaseType-3 LSAs absent inside area 2.

Break it, then fix it

Introduce each fault, observe the symptom, then open the hint.

breakMTU mismatch on one link

Neighbors stay stuck in EXSTART/EXCHANGE. Match the MTU (or ip ospf mtu-ignore as a last resort).

breakStub flag only on one side

No adjacency: the hello options field differs. Configure stub on both routers.

breakDifferent hello/dead timers

Neighbor never appears. Align timers per link.

Key takeaways

  • Areas limit the flooding scope; ABRs are where you summarise.
  • Stub areas trade detail for stability: a default route is often enough.
  • Most adjacency problems are a parameter mismatch: area, MTU, timers, auth, stub flag.
