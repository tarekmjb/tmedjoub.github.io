Automatisation réseau Ansible

Utiliser Ansible pour sauvegarder la configuration de chaque routeur, déployer une base NTP et journalisation standard, et prouver l’idempotence avec le mode check.

Objectif

Utiliser Ansible pour sauvegarder la configuration de chaque routeur, déployer une base NTP et journalisation standard, et prouver l’idempotence avec le mode check.

Prérequis

  • EVE-NG (Community ou Pro) avec les images indiquées dans la topologie.
  • Accès console à chaque nœud ; bases de la CLI.

Topologie & adressage

ÉquipementInterfaceAdresse / rôle
Ansible hosteth010.99.0.5/24
R1–R3Gi0/3 (mgmt)10.99.0.11–13/24

Construction pas à pas

1. Inventaire

Grouper les routeurs et définir la connexion réseau. Le mot de passe vient d’Ansible Vault.

inventory.yml
all:
  children:
    ios:
      hosts:
        r1: { ansible_host: 10.99.0.11 }
        r2: { ansible_host: 10.99.0.12 }
        r3: { ansible_host: 10.99.0.13 }
      vars:
        ansible_network_os: cisco.ios.ios
        ansible_connection: ansible.netcommon.network_cli
        ansible_user: netadmin
        ansible_password: "{{ vault_ios_password }}"
        ansible_become: true
        ansible_become_method: enable

2. Sauvegarder les configurations

Un fichier par équipement dans ./backups.

backup.yml
- name: Backup running configs
  hosts: ios
  gather_facts: false
  tasks:
    - name: Save running-config
      cisco.ios.ios_config:
        backup: true
        backup_options:
          dir_path: ./backups
          filename: "{{ inventory_hostname }}.cfg"

3. Déployer une base commune

Seules les lignes manquantes sont envoyées. La config n’est sauvegardée que si quelque chose a changé.

baseline.yml
- name: NTP and logging baseline
  hosts: ios
  gather_facts: false
  tasks:
    - name: Ensure NTP and syslog
      cisco.ios.ios_config:
        lines:
          - ntp server 10.99.0.1
          - logging host 10.99.0.20
          - service timestamps log datetime msec
        save_when: changed

Vérifier

CommandeCe que vous devez voir
ansible-playbook -i inventory.yml backup.ymlUn .cfg par routeur dans ./backups.
ansible-playbook -i inventory.yml baseline.yml --check --diffAffiche les lignes qui seraient ajoutées, sans rien modifier.
ansible-playbook -i inventory.yml baseline.yml (run twice)Second passage : changed=0 (idempotent).
ansible ios -i inventory.yml -m cisco.ios.ios_command -a "commands='show run | i ntp'"Ligne NTP présente sur chaque routeur.

Casser, puis réparer

Introduisez chaque panne, observez le symptôme, puis ouvrez l’indice.

panneClé d’hôte SSH inconnue

Connexion refusée au premier passage. Ajouter les clés à known_hosts (ne pas désactiver la vérification en production).

panneNiveau de privilège insuffisant

Les commandes de config échouent. Définir become avec la méthode enable.

panneLigne écrite différemment sur l’équipement

La tâche indique changed à chaque passage. Reprendre exactement la syntaxe de la running-config.

À retenir

  • Sauvegarder avant d’automatiser des changements.
  • Le mode check avec diff, c’est votre revue de changement.
  • L’idempotence (changed=0 au second passage) prouve que le playbook décrit un état, pas un script.
