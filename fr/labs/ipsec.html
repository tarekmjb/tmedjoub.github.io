VPN IPsec site à site

Objectif

Relier deux sites via internet avec un tunnel IKEv2 route-based (VTI) : AES-256, SHA-256, groupe DH 14 avec PFS, puis dépanner les échecs de négociation classiques.

Prérequis

  • EVE-NG (Community ou Pro) avec les images indiquées dans la topologie.
  • Accès console à chaque nœud ; bases de la CLI.

Topologie & adressage

ÉquipementInterfaceAdresse / rôle
R1Gi0/0 (WAN)198.51.100.1
R2Gi0/0 (WAN)198.51.100.2
R1 / R2Tunnel010.255.0.1/30 · 10.255.0.2/30
R1 / R2LAN192.168.1.1/24 · 192.168.2.1/24

Construction pas à pas

1. Proposition, politique et keyring IKEv2

Les paramètres de phase 1 doivent être identiques des deux côtés.

R1
crypto ikev2 proposal PROP-AES256
 encryption aes-cbc-256
 integrity sha256
 group 14
crypto ikev2 policy POL-1
 proposal PROP-AES256
crypto ikev2 keyring KR-R2
 peer R2
  address 198.51.100.2
  pre-shared-key <redacted>
crypto ikev2 profile PROF-R2
 match identity remote address 198.51.100.2 255.255.255.255
 authentication remote pre-share
 authentication local pre-share
 keyring local KR-R2

2. Profil IPsec (phase 2)

ESP AES-256 / SHA-256 avec PFS groupe 14.

R1
crypto ipsec transform-set TS-AES256 esp-aes 256 esp-sha256-hmac
 mode tunnel
crypto ipsec profile IPSEC-R2
 set transform-set TS-AES256
 set ikev2-profile PROF-R2
 set pfs group14

3. Interface tunnel et routage

La VTI est une interface classique : on y route le LAN distant. Le MSS est ajusté pour l’en-tête IPsec.

R1
interface Tunnel0
 ip address 10.255.0.1 255.255.255.252
 ip mtu 1400
 ip tcp adjust-mss 1360
 tunnel source GigabitEthernet0/0
 tunnel destination 198.51.100.2
 tunnel mode ipsec ipv4
 tunnel protection ipsec profile IPSEC-R2
!
ip route 192.168.2.0 255.255.255.0 Tunnel0

Casser, puis réparer

Introduisez chaque panne, observez le symptôme, puis ouvrez l’indice.

panneClé pré-partagée différente

IKE_AUTH échoue ; le debug indique un échec d’authentification. Ressaisir la clé des deux côtés.

pannePropositions différentes

NO_PROPOSAL_CHOSEN dans les logs. Comparer chiffrement, intégrité et groupe DH.

panneTunnel actif, pas de trafic

Encaps reste à 0 : la route vers le LAN distant manque, ou un pare-feu bloque l’UDP 500/4500.

À retenir

  • Les VPN route-based passent à l’échelle : on ajoute une route (ou BGP) au lieu de modifier des ACL crypto.
  • Lire l’erreur : NO_PROPOSAL_CHOSEN, AUTH_FAILED et TS_UNACCEPTABLE pointent chacun vers une correction différente.
  • Ajuster le MSS sur les tunnels pour éviter les problèmes de fragmentation.
