Objectif

Monter de l’eBGP entre trois systèmes autonomes, annoncer les préfixes LAN, puis modifier le chemin utilisé par R1 vers l’AS65003 avec la local preference, sans toucher au chemin AS le plus court.

Prérequis

  • EVE-NG (Community ou Pro) avec les images indiquées dans la topologie.
  • Accès console à chaque nœud ; bases de la CLI.

Topologie & adressage

ÉquipementInterfaceAdresse / rôle
R1Gi0/0 → R210.0.12.1/30
R1Gi0/1 → R310.0.13.1/30
R2Gi0/0 → R110.0.12.2/30
R2Gi0/1 → R310.0.23.1/30
R3Gi0/0 → R210.0.23.2/30
R3Gi0/1 → R110.0.13.2/30
R1 / R3Gi0/2 (LAN)172.16.1.1/24 · 172.16.3.1/24

Construction pas à pas

1. Monter les sessions eBGP

Un voisin par lien direct, activé dans l’address-family IPv4.

R1
router bgp 65001
 bgp router-id 1.1.1.1
 bgp log-neighbor-changes
 neighbor 10.0.12.2 remote-as 65002
 neighbor 10.0.13.2 remote-as 65003
 address-family ipv4
  neighbor 10.0.12.2 activate
  neighbor 10.0.13.2 activate
  network 172.16.1.0 mask 255.255.255.0

2. Annoncer les LAN

Une commande network ne fonctionne que si le préfixe exact est déjà dans la table de routage.

R3
router bgp 65003
 bgp router-id 3.3.3.3
 neighbor 10.0.23.1 remote-as 65002
 neighbor 10.0.13.1 remote-as 65001
 address-family ipv4
  neighbor 10.0.23.1 activate
  neighbor 10.0.13.1 activate
  network 172.16.3.0 mask 255.255.255.0

3. Changer le meilleur chemin

Par défaut, R1 joint 172.16.3.0/24 en direct (chemin AS le plus court). On augmente la local preference des routes reçues de R2 pour que R1 préfère passer par l’AS65002.

R1
route-map FROM-R2 permit 10
 set local-preference 200
!
router bgp 65001
 address-family ipv4
  neighbor 10.0.12.2 route-map FROM-R2 in
!
clear ip bgp 10.0.12.2 soft in

Vérifier

CommandeCe que vous devez voir
show ip bgp summaryLes deux voisins affichent un nombre de préfixes, pas Idle/Active.
show ip bgp 172.16.3.0Deux chemins ; le meilleur via 10.0.12.2 avec localpref 200.
show ip route bgp172.16.3.0/24 via 10.0.12.2 après la modification.
traceroute 172.16.3.1 source 172.16.1.1Passe par R2.

Casser, puis réparer

Introduisez chaque panne, observez le symptôme, puis ouvrez l’indice.

panneremote-as erroné d’un côté

La session oscille entre Idle et Active ; les logs montrent une NOTIFICATION "bad peer AS". Corriger l’ASN.

panneCommande network avec un mauvais masque

Le préfixe n’apparaît jamais dans show ip bgp : aucune correspondance exacte dans la RIB.

panneRoute-map appliquée mais rien ne change

La politique ne s’applique qu’aux nouvelles mises à jour : faire un clear soft en entrée.

À retenir

  • L’eBGP, c’est du routage par politique : c’est vous qui choisissez le chemin, pas la métrique.
  • La local preference est évaluée avant la longueur du chemin AS et reste interne à votre AS.
  • Toujours faire un clear soft après une modification de politique en entrée.
