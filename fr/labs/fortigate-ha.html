Objectif

Monter un cluster FGCP actif-passif avec deux liens de heartbeat, des interfaces surveillées et la reprise de session, puis faire tomber le primaire et vérifier que les sessions survivent.

Prérequis

  • EVE-NG (Community ou Pro) avec les images indiquées dans la topologie.
  • Accès console à chaque nœud ; bases de la CLI.

Topologie & adressage

ÉquipementInterfaceAdresse / rôle
Clusterport1 (WAN)203.0.113.2/29
Clusterport2 (LAN)10.1.0.1/24
FG-A / FG-Bport5 (mgmt)10.99.0.11 · 10.99.0.12
Heartbeatport3 / port4169.254.0.x (FGCP, automatic)

Construction pas à pas

1. Même firmware, même modèle

FGCP ne se forme qu’entre modèles et versions identiques. Vérifier avec get system status.

FG-A / FG-B
get system status

2. Paramètres HA (primaire)

Deux liens de heartbeat, ports de données surveillés, reprise de session.

FG-A
config system ha
    set group-name "FG-CLUSTER"
    set group-id 10
    set mode a-p
    set password ENC ********
    set hbdev "port3" 50 "port4" 50
    set session-pickup enable
    set override disable
    set priority 200
    set monitor "port1" "port2"
    set ha-mgmt-status enable
    config ha-mgmt-interfaces
        edit 1
            set interface "port5"
            set gateway 10.99.0.254
        next
    end
end

3. Secondaire

Mêmes paramètres, priorité plus basse. La configuration se synchronise depuis le primaire une fois le cluster formé.

FG-B
config system ha
    set group-name "FG-CLUSTER"
    set group-id 10
    set mode a-p
    set password ENC ********
    set hbdev "port3" 50 "port4" 50
    set session-pickup enable
    set override disable
    set priority 100
    set monitor "port1" "port2"
end

Vérifier

CommandeCe que vous devez voir
get system ha statusLes deux unités listées, primaire et secondaire identifiés.
diagnose sys ha checksum clusterChecksums identiques sur les deux unités.
execute ha manage 1 adminCLI du secondaire depuis le primaire.
diagnose sys session list (on secondary)Sessions présentes quand session-pickup est actif.

Casser, puis réparer

Introduisez chaque panne, observez le symptôme, puis ouvrez l’indice.

panneFirmwares différents

Aucun cluster ne se forme. Mettre à niveau une unité avant de la joindre.

panneCoupure de l’unique lien de heartbeat

Les deux unités deviennent primaires (split brain). Toujours utiliser deux liens de heartbeat.

pannePort surveillé tombé sur le primaire

Bascule vers le secondaire, comme prévu. Avec override désactivé, il le reste après le retour.

À retenir

  • Deux heartbeats, des ports surveillés et la reprise de session sont le minimum.
  • Override désactivé évite une seconde bascule quand l’ancien primaire revient.
  • Tester la bascule avec des sessions actives, pas seulement des pings.
