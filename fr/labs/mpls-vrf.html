MPLS L3VPN & VRF

Construire un petit cœur opérateur (OSPF + LDP), puis un L3VPN client : VRF sur les PE, MP-BGP VPNv4 entre les loopbacks des PE et eBGP vers les CE.

Objectif

Construire un petit cœur opérateur (OSPF + LDP), puis un L3VPN client : VRF sur les PE, MP-BGP VPNv4 entre les loopbacks des PE et eBGP vers les CE.

Prérequis

  • EVE-NG (Community ou Pro) avec les images indiquées dans la topologie.
  • Accès console à chaque nœud ; bases de la CLI.

Construction pas à pas

1. Cœur : OSPF + LDP

Chaque interface du cœur fait tourner OSPF et LDP. Les loopbacks servent de router-id LDP et de source BGP.

PE1 / P / PE2
mpls label protocol ldp
mpls ldp router-id Loopback0 force
!
interface GigabitEthernet0/0
 mpls ip
!
router ospf 1
 network 10.0.0.0 0.0.0.255 area 0
 network 10.1.0.0 0.0.255.255 area 0

2. VRF client sur le PE

Le RD rend les routes uniques ; les route targets décident qui les importe.

PE1
vrf definition CUST-A
 rd 65000:1
 address-family ipv4
  route-target export 65000:1
  route-target import 65000:1
!
interface GigabitEthernet0/2
 vrf forwarding CUST-A
 ip address 10.10.1.1 255.255.255.252

3. MP-BGP VPNv4 + eBGP PE–CE

L’iBGP entre loopbacks des PE transporte les routes VPNv4 avec les communautés étendues.

PE1
router bgp 65000
 neighbor 10.0.0.3 remote-as 65000
 neighbor 10.0.0.3 update-source Loopback0
 address-family vpnv4
  neighbor 10.0.0.3 activate
  neighbor 10.0.0.3 send-community extended
 address-family ipv4 vrf CUST-A
  neighbor 10.10.1.2 remote-as 65101
  neighbor 10.10.1.2 activate

Vérifier

CommandeCe que vous devez voir

show bgp vpnv4 unicast allPréfixes client avec le RD 65000:1.
ping vrf CUST-A 10.10.2.2Joignabilité CE à CE à travers le cœur.

Casser, puis réparer

Introduisez chaque panne, observez le symptôme, puis ouvrez l’indice.

pannePas de send-community extended

Les routes VPNv4 arrivent sans route target et ne sont pas importées dans la VRF.

panneRoute targets différentes

Les routes sont dans la table VPNv4 mais pas dans la table VRF de l’autre PE.

panneLDP désactivé sur un lien du cœur

BGP fonctionne, mais le chemin labellisé est rompu et le trafic VPN est perdu sur le P.

À retenir

  • RD = unicité, RT = appartenance. Ce n’est pas la même chose.
  • Le P ne connaît rien des clients : c’est ce qui fait passer MPLS à l’échelle.
  • Vérifier séparément le plan de contrôle (BGP) et le plan de données (labels).
