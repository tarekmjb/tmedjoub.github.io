SD-WAN : sélection de chemin & bascule

Donner deux liens internet à une agence FortiGate, les mesurer avec des sondes SLA, orienter le trafic par application, puis dégrader un lien (latence, perte) pour observer le changement de décision.

Objectif

Donner deux liens internet à une agence FortiGate, les mesurer avec des sondes SLA, orienter le trafic par application, puis dégrader un lien (latence, perte) pour observer le changement de décision.

Prérequis

  • EVE-NG (Community ou Pro) avec les images indiquées dans la topologie.
  • Accès console à chaque nœud ; bases de la CLI.

Topologie & adressage

ÉquipementInterfaceAdresse / rôle
FG-BRANCHwan1 / wan2100.64.1.2/30 · 100.64.2.2/30
ISP-1 / ISP-2eth1 → branch100.64.1.1 · 100.64.2.1
FG-HQLAN probe server10.1.0.10

Construction pas à pas

1. Membres et zone

Les deux interfaces WAN dans une zone SD-WAN, chacune avec sa passerelle.

FG-BRANCH
config system sdwan
    set status enable
    config members
        edit 1
            set interface "wan1"
            set gateway 100.64.1.1
        next
        edit 2
            set interface "wan2"
            set gateway 100.64.2.1
        next
    end
end

2. Sonde SLA

Sondes toutes les 500 ms ; un membre est mort après 3 échecs et rétabli après 5 succès.

FG-BRANCH
config system sdwan
    config health-check
        edit "SLA-HQ"
            set server "10.1.0.10"
            set protocol ping
            set interval 500
            set failtime 3
            set recoverytime 5
            set members 1 2
            config sla
                edit 1
                    set latency-threshold 100
                    set jitter-threshold 20
                    set packetloss-threshold 2
                next
            end
        next
    end
end

3. Règles d’orientation

La VoIP reste sur wan1 tant que le SLA est respecté ; le trafic de masse préfère wan2.

FG-BRANCH
config system sdwan
    config service
        edit 1
            set name "VOIP"
            set mode sla
            set dst "VOIP-SERVERS"
            config sla
                edit "SLA-HQ"
                    set id 1
                next
            end
            set priority-members 1 2
        next
        edit 2
            set name "BULK"
            set mode manual
            set dst "BACKUP-SERVERS"
            set priority-members 2 1
        next
    end
end

4. Dégrader un lien

Sur le nœud Linux ISP-1, ajouter latence et perte, puis les retirer.

ISP-1 (Linux)
# add 150 ms delay and 5 % loss towards the branch
tc qdisc add dev eth1 root netem delay 150ms loss 5%
# restore
tc qdisc del dev eth1 root

Vérifier

CommandeCe que vous devez voir
diagnose sys sdwan health-checkLatence, gigue, perte et état SLA par membre.
diagnose sys sdwan serviceLe membre choisi par la règle VOIP à l’instant.
diagnose sniffer packet any 'icmp' 4Les sondes sortent sur les deux membres.
execute ping-options source … + pingTrafic de test continu pendant la dégradation.

Casser, puis réparer

Introduisez chaque panne, observez le symptôme, puis ouvrez l’indice.

panneServeur de sonde injoignable sur un membre

Ce membre est toujours mort. Vérifier le routage et la politique de pare-feu sur le chemin de la sonde.

panneSeuils trop serrés

Le trafic oscille entre les liens. Relever les seuils ou le temps de rétablissement.

panneLa règle ne correspond jamais

Le trafic tombe dans la règle implicite. Vérifier l’ordre des règles et l’objet destination.

À retenir

  • Temps de détection ≈ interval × failtime. À ajuster par application.
  • Un lien peut être actif et pourtant inutilisable : les sondes SLA le détectent.
  • Toujours tester la bascule avec une vraie dégradation, pas seulement un câble débranché.
