Supervision SNMPv3 avec Zabbix

Objectif

Sécuriser SNMP en v3 authPriv sur un commutateur, le tester depuis le serveur Zabbix avec snmpwalk, ajouter l’équipement avec un modèle constructeur et déclencher une alerte en coupant une interface.

Prérequis

  • EVE-NG (Community ou Pro) avec les images indiquées dans la topologie.
  • Accès console à chaque nœud ; bases de la CLI.

Topologie & adressage

ÉquipementInterfaceAdresse / rôle
Zabbix servereth010.10.50.20/24
SW1Vlan50 (mgmt)10.10.50.2/24

Construction pas à pas

1. SNMPv3 sur le commutateur

authPriv (SHA + AES), vue en lecture seule, et une ACL pour que seul Zabbix puisse interroger.

SW1
ip access-list standard ACL-NMS
 permit 10.10.50.20
!
snmp-server view NMS-VIEW iso included
snmp-server group NMS v3 priv read NMS-VIEW access ACL-NMS
snmp-server user zabbix NMS v3 auth sha <redacted> priv aes 128 <redacted>
snmp-server host 10.10.50.20 version 3 priv zabbix
snmp-server enable traps snmp linkdown linkup

2. Tester depuis le serveur

Si snmpwalk échoue, Zabbix échouera aussi. Corriger d’abord ici.

Zabbix server
snmpwalk -v3 -l authPriv -u zabbix \
  -a SHA -A '<auth-pass>' -x AES -X '<priv-pass>' \
  10.10.50.2 1.3.6.1.2.1.1

3. Ajouter l’hôte dans Zabbix

Collecte de données → Hôtes → Créer un hôte : interface SNMP 10.10.50.2, identifiants SNMPv3 authPriv, modèle du constructeur (par exemple Cisco IOS by SNMP).

Zabbix UI
Host name      : SW1
Interface      : SNMP 10.10.50.2:161
SNMP version   : SNMPv3
Security level : authPriv
Auth / Priv    : SHA / AES
Template       : Cisco IOS by SNMP

Vérifier

CommandeCe que vous devez voir
snmpwalk … 1.3.6.1.2.1.1sysDescr, sysName et sysUpTime retournés.
Zabbix → Monitoring → Latest dataItems interfaces et CPU mis à jour.
shutdown Gi0/5 on SW1Le problème link down apparaît dans Zabbix dans l’intervalle de collecte.
no shutdownLe problème se résout automatiquement.

Casser, puis réparer

Introduisez chaque panne, observez le symptôme, puis ouvrez l’indice.

panneMot de passe auth ou priv erroné

snmpwalk renvoie un échec d’authentification ou une erreur de déchiffrement. Recréer l’utilisateur.

panneL’ACL n’inclut pas le serveur

Uniquement des timeouts. Vérifier les compteurs de l’ACL.

panneNiveau de sécurité différent

Zabbix en authNoPriv face à un utilisateur priv : aucune donnée. Aligner sur authPriv.

À retenir

  • SNMPv1/v2c envoient la communauté en clair ; utiliser v3 authPriv.
  • Toujours valider SNMP avec snmpwalk avant d’accuser l’outil de supervision.
  • Partir des modèles constructeur, puis ajuster les déclencheurs pour réduire le bruit.
